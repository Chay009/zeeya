# Zeeya Home calendar library research

Checked 2026-08-24. Zeeya currently targets Expo 57 / React Native 0.86.0, React 19.2.3, Reanimated 4.5.0, Gesture Handler 2.32, and Worklets 0.10 ([local package manifest](../../package.json)). The target behavior is a correct month grid with horizontal month navigation, while preserving the existing day cell: day number, signed transaction-amount pill, and today highlight.

## Recommendation

Use [Wix `react-native-calendars`](https://github.com/wix/react-native-calendars) for the first implementation. Its `Calendar`/`CalendarList` APIs cover month layout, adjacent-month handling, six-week fixed grids, month navigation/swiping, and custom `dayComponent` rendering. The project explicitly documents Expo compatibility, accessibility support, and a JavaScript-only implementation with no native module linking ([README](https://github.com/wix/react-native-calendars), [calendar source](https://github.com/wix/react-native-calendars/blob/master/src/calendar/index.tsx), [custom day source](https://github.com/wix/react-native-calendars/blob/master/src/calendar/day/index.tsx)).

Implement a custom day component that reads the existing per-date transaction totals, renders the unchanged pill/highlight styling, and forwards the library-provided `onPress`, `onLongPress`, and `accessibilityLabel`. The source shows that the library computes a full date/today/marking accessibility label and passes it to a custom day component. Use `Calendar` with `enableSwipeMonths` for the current card; use `CalendarList` only if the card needs a scrollable month range ([CalendarList source](https://github.com/wix/react-native-calendars/blob/master/src/calendar-list/index.tsx)).

This is the lowest-risk choice for preserving the visual design. It is not an explicit RN 0.86 certification—the repository’s current development manifest uses RN 0.73.11—so the eventual change should include an Expo 57/RN 0.86 smoke build before adoption ([package manifest](https://github.com/wix/react-native-calendars/blob/master/package.json)).

## HeroUI Native

HeroUI Native does **not** currently provide a Calendar component. Its official component directory lists primitives such as accordion, card, dialog, select, tabs, and toast, but no calendar or date-grid component ([official component directory](https://github.com/heroui-inc/heroui-native/tree/main/src/components)). It can style surrounding controls, but it cannot supply the corrected month math, paging, or custom day-cell behavior needed here.

## Decision for implementation

1. Pilot Wix `react-native-calendars` with a custom `dayComponent` and the existing transaction-date map.
2. Lock the grid height with `showSixWeeks` if the Home card must not jump between four-, five-, and six-row months.
3. Keep the current chart custom; none of these calendar libraries improves the chart requirement.
4. If Wix cannot preserve the exact pill layout or RN 0.86 smoke testing exposes a compatibility issue, evaluate `super-calendar` next; do not choose Quidone for a new dependency.
